# splits: the frozen holdout and the frozen nested CV splits

**Status:** built.
- **Holdout:** build step 1, command `python run.py holdout`.
- **CV splits:** build step 2, command `python run.py splits`.

Both are created **once**, saved under `outputs/frozen/`, and their SHA-256 is written into `config.yaml`. Every later run checks the file against that hash before using it. Both commands refuse to run if the file already exists, so a split can't be regenerated by accident. Every model, comparison and Phase 2 analysis uses these same splits, so all comparisons are paired.

## Stratification rule (`strata_labels`)

Patients are stratified on **outcome × cohort × chemotherapy**: 20 strata, the smallest with 13 patients overall and 11 in the training rows. A stratum smaller than the required count is merged across cohorts within the same outcome × chemotherapy cell, and the merge is returned for logging. No merge has been needed so far.

## 1. Holdout (`make_holdout`, `load_holdout`)

- **Split:** 20% of the 1,904 patients go to the holdout (381) and 1,523 are training rows. It uses `train_test_split(stratify=strata, test_size=0.20, random_state=42)`.
- **File:** `outputs/frozen/holdout.csv` (patient_id, set = train/holdout, stratum). Its hash is `holdout.sha256` in config.
- **Use:** the holdout is scored **once, at the end**. Until then the only thing allowed to read its rows is the balance check in the modelling-mode EDA. `training_ids(cfg, ds)` returns the training rows and checks the hash first.

## 2. Nested CV splits (`make_cv_splits`, `load_cv_splits`)

- **Scope:** training rows only. The holdout never appears in these splits.
- **Outer:** `StratifiedKFold(5)` repeated twice (seeds 42 + repeat), giving 10 outer splits named `r0o0` … `r1o4`. Test folds hold 304–305 patients and training parts 1,218–1,219.
- **Inner:** each outer training part gets `StratifiedKFold(3)` (seed 42 + 1000 × (repeat + 1) + fold), re-stratified within that part.
- **File:** `outputs/frozen/cv_splits.csv`, one row per (split, patient), with columns split_id, repeat, outer_fold, patient_id, role (`train`/`test`) and inner_fold (0–2 for training rows, −1 for test rows). Its hash is `cv.splits_sha256` in config.
- **`load_cv_splits`** checks the hash, that the splits cover exactly the training rows, and the number of splits.

Balance is checked by the modelling-mode EDA (item 10): the holdout against the training rows, and every outer test part against its training part. Stratified variables must not differ by more than 2 points (the run fails otherwise); other variables only produce warnings.

## Tests
